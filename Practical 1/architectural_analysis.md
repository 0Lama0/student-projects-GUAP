# Технический анализ сайта «ИП Филюта»

## 1. Краткий обзор

Сайт представляет собой одностраничный сайт-визитку клининговых услуг.
Основной файл --- `index_GPT.html`. В нём находятся HTML-разметка,
встроенный CSS в блоке `<style>` и JavaScript в блоке `<script>`.

По доступному исходнику подтверждаются: - разделы «О компании»,
«Услуги», «Преимущества», «Наши работы», «Контакты»; - мобильная
навигация с переключателем `menu-toggle` и меню `main-nav`; -
автоматическая подстановка текущего года в `current-year`; -
изображения, включая изображения с Unsplash; - обработчики мобильного
меню, клавиши Escape и изменения ширины окна; - CSS-правило
`prefers-reduced-motion` для пользователей, предпочитающих уменьшенное
движение.

**Важно:** наличие отдельных файлов `style.css` и `script.js`, их
полнота и корректность требуют проверки непосредственно в папке проекта.
Нельзя считать их готовыми только потому, что они упомянуты в прежнем
анализе.

## 2. Подтверждённые особенности и риски

### 2.1. CSS и JavaScript встроены в HTML

Стили находятся внутри `<style>`, а скрипт --- внутри `<script>`. Это не
обязательно ошибка для небольшого статического сайта, но затрудняет
поддержку и повторное использование кода.

**Рекомендация:** сначала точно перенести существующий CSS в
`style.css`, а JavaScript --- в `script.js`, не переписывая их логику.
После проверки подключить файлы из HTML.

### 2.2. При переносе важно сохранить порядок и поведение

Если в HTML несколько блоков `<style>` или `<script>`, порядок их
содержимого может влиять на результат. Нельзя заменять исходный код
приблизительно сгенерированными стилями или функциями.

**Рекомендация:** сохранить резервную копию HTML, извлечь весь исходный
код автоматически и сравнить количество блоков, размеры файлов и
поведение сайта до и после переноса.

### 2.3. Внешние изображения

В доступном HTML встречаются ссылки на изображения Unsplash. При
проверке следует убедиться, что изображения загружаются, имеют
подходящие альтернативные описания и не ломают вёрстку при медленном
соединении.

### 2.4. Интерактивность

В исходнике присутствует JavaScript мобильного меню. После переноса
нужно проверить открытие и закрытие меню, переход по ссылкам, закрытие
клавишей Escape и возврат к обычной навигации при увеличении ширины
окна.

## 3. Что пока нельзя утверждать

Без проверки всех файлов и запуска сайта нельзя достоверно утверждать,
что: - все функции и селекторы, упомянутые в предыдущем отчёте,
действительно существуют; - CSS или JavaScript содержат конкретные
ошибки; - тесты успешно пройдены; - перенос сократит число строк до
определённого значения или ускорит сайт на заданный процент; - проекту
необходимы React, Next.js, TypeScript, Vite, Webpack, npm-сборка или
CI/CD.

Такие утверждения следует либо подтвердить проверкой, либо удалить из
отчёта.

## 4. Минимальная структура проекта

Для небольшого статического сайта достаточно начать с простой структуры:

``` text
project/
├── index_GPT.html
├── style.css
├── script.js
├── images/
└── fonts/
```

Папки `images/` и `fonts/` нужны только в том случае, если
соответствующие ресурсы действительно хранятся локально. Не следует
добавлять сборщик, зависимости или сложную архитектуру без конкретной
необходимости.

## 5. Минимальный план работ

1.  **Сделать резервную копию** исходного `index_GPT.html`.
2.  **Извлечь CSS без переписывания** содержимого всех блоков `<style>`
    в `style.css`.
3.  **Извлечь JavaScript без переписывания** содержимого всех блоков
    `<script>` в `script.js`. Отдельно проверить, нет ли скриптов
    сторонних библиотек или скриптов, которые должны остаться в HTML.
4.  **Подключить файлы** в HTML, сохранив порядок выполнения скриптов.
    Если скрипт обращается к элементам страницы, убедиться, что он
    запускается после создания этих элементов.
5.  **Сравнить исходную и обновлённую версии** в браузере на компьютере
    и телефоне.
6.  **Проверить консоль разработчика** на ошибки JavaScript и загрузку
    ресурсов.
7.  **Удалить резервную копию или встроенные блоки только после успешной
    проверки**, сохранив возможность отката.

## 6. Критерии проверки

-   Страница открывается без ошибок.
-   Все разделы и ссылки навигации работают.
-   Мобильное меню открывается и закрывается корректно.
-   Формы, карусель и прочие интерактивные элементы (если они
    присутствуют в итоговом исходнике) работают так же, как до
    изменений.
-   Изображения, шрифты и стили загружаются.
-   На мобильной ширине нет горизонтальной прокрутки и критичных
    наложений.
-   В консоли нет новых ошибок.
-   Внешний вид до и после переноса не отличается намеренно.

## 7. Риски

-   Потеря части CSS или JavaScript при ручном копировании.
-   Изменение приоритета стилей или порядка выполнения скриптов.
-   Двойное подключение скрипта после переноса.
-   Ошибки путей к CSS, JS, изображениям и шрифтам.
-   Удаление встроенного кода до того, как новые файлы проверены.

## Итог

Для этого проекта разумный первый шаг --- не переписывание сайта на
другой фреймворк, а аккуратное разделение существующих HTML, CSS и
JavaScript с проверкой сохранения поведения. Любые дальнейшие улучшения
следует планировать после проверки реальных файлов и тестирования в
браузере.
